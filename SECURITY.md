# Security policy

For the v0.3 release, the proposed supported line is the latest 0.3.x converter
and matching specification. Older versions should upgrade; no long-term support
or response-time commitment is made by this draft.

Report suspected vulnerabilities privately, including affected version/commit,
reproduction steps, impact, and any safe proof of concept. Avoid posting
credentials, private genome data, or exploit details in a public issue. Maintainers
should acknowledge receipt, assess severity, coordinate a fix and disclosure,
and credit the reporter with consent. Schema correctness issues without security
impact can use ordinary issues.

## Reporting channel awaiting confirmation

A private maintainer reporting channel must be confirmed before this policy is
adopted. If GitHub's private vulnerability reporting is enabled for this repo,
use the Security tab's “Report a vulnerability” action; this document does not
assume that feature is enabled. Maintainers must supply the fallback contact and
supported-version policy before release. Do not invent response deadlines.
